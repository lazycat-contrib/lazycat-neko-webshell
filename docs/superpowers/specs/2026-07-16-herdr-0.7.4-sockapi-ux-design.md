# Herdr 0.7.4 SockAPI and Interaction Adaptation Design

## Status

Approved for implementation. The user asked to update the sibling Herdr
checkout, adapt WebShell to the latest SockAPI, and apply worthwhile
interaction improvements without another confirmation round.

## Goal

Update the sibling `herdr` checkout to its latest tracked `origin/master`,
sync WebShell's embedded JSON SockAPI contract with Herdr 0.7.4, and use the
new event and terminal-title capabilities to make Herdr navigation react
immediately and read more clearly.

The selected upstream revision is `a22454f27ce096585e19d1787dba43f56d1505cf`.
It reports version `0.7.4`, contains the stable `v0.7.4` release, and includes
the post-release protocol guard, graphics-stream race, and live-handoff plugin
preservation fixes.

## Selected scope

This release will:

- fast-forward `../herdr` from `3661d99` to the latest tracked
  `origin/master`;
- update `src/herdr_socket_contract.json` from Herdr 0.7.3 to the JSON portion
  of the 0.7.4 schema;
- add the five new JSON methods and two new subscriptions to the allowlists;
- preserve workspace metadata tokens and pane presentation metadata from
  `session.snapshot` in the WebShell Herdr state;
- apply `workspace.metadata_updated` and `pane.updated` event snapshots
  immediately instead of waiting for repeated state polls;
- use explicit pane metadata titles and safety-normalized terminal titles as
  a fallback for generic Herdr tab labels and as richer tab tooltips;
- recognize horizontal SGR wheel reports in the existing per-frame Herdr input
  batcher; and
- release the WebShell changes as version `0.5.33` with tag `v0.5.33`.

## SockAPI contract

The protocol remains `16` and the schema version remains `1`.

New JSON methods:

- `workspace.report_metadata`
- `pane.graphics.set`
- `pane.graphics.clear`
- `pane.graphics.info`
- `popup.close`

New subscriptions:

- `workspace.metadata_updated`
- `pane.updated`

The embedded contract will contain 85 methods and 26 subscriptions. Method
allowlisting and event subscription support remain separate checks.

`pane.graphics.stream` is deliberately excluded. It uses a dedicated Unix
socket and a raw binary frame protocol, while the existing WebShell bridge is
newline-delimited JSON. Adding it to the JSON allowlist would advertise a
method the bridge cannot safely carry.

## State model

`HerdrBridgeState` will retain the focused session snapshot's pane
presentation data in a focused `HerdrPaneInfo` type:

- pane, workspace, and tab ids;
- focused state;
- metadata title;
- raw and spinner-stripped terminal titles;
- detected and displayed agent names;
- semantic agent status; and
- custom metadata tokens.

`HerdrWorkspaceInfo` will retain its metadata token map. Token values remain
data, not automatically rendered UI. Herdr lets users configure which custom
tokens are visible, so WebShell must not expose every reported token or guess
that arbitrary metadata is safe or useful to show.

For protocol 16, the backend reads workspaces, tabs, and panes from the single
`session.snapshot` response. The existing protocol 14/15 fallback continues to
return workspace and tab lists with an empty pane metadata collection; older
servers therefore keep working without extra pane polling.

## Event data flow

The event bridge will subscribe globally to `workspace.metadata_updated` and
`pane.updated`, in addition to the existing lifecycle events. Per-pane agent
status subscriptions remain scoped to the known pane ids. The intentionally
disabled `pane.scroll_changed` subscription stays disabled because it causes
frequent pane refresh work and is not needed for the current UI.

```text
Herdr event socket
       |
       +-- workspace.metadata_updated -- replace matching workspace snapshot
       |
       +-- pane.updated ---------------- replace matching pane snapshot
       |
       +-- lifecycle/layout event ------ existing debounced snapshot refresh
                                              and subscription reconciliation
```

A narrow Herdr state-event module will validate and apply complete resource
snapshots. `main.ts` will only parse the envelope, call the state helper,
render when it changed, and retain the existing refresh scheduling for
lifecycle events.

Metadata-only events will be silent in the global status bar. Their complete
event payloads make the repeated `0/300/900/1800/3000 ms` settle refresh
sequence unnecessary. Lifecycle events still use the existing settle path
because creation, movement, focus, and close operations may affect multiple
collections and event subscriptions.

## Tab-label interaction

Herdr's explicit tab label always wins. A pane-derived title is used only when
the Herdr tab label is generic, empty, or only repeats its number.

The focused pane detail priority is:

1. explicit pane metadata `title`;
2. `terminal_title_stripped`;
3. `display_agent`;
4. raw `terminal_title`;
5. detected `agent`.

Custom token maps are not part of this fallback. This follows Herdr's
separation between configured presentation tokens and arbitrary reported
metadata.

Examples:

- explicit tab `tests` stays `tests`, with `tests · pytest` in its tooltip;
- generic tab `1` may display `Refactor auth middleware` from pane metadata;
- a Codex spinner title is shown without its leading spinner when Herdr
  provides `terminal_title_stripped`;
- old Herdr servers with no pane metadata keep the existing number-only label.

## Horizontal wheel handling

The browser-to-Restty path already preserves `WheelEvent.deltaX`, and Herdr
0.7.4 now forwards horizontal wheel reports to pane applications. WebShell's
Herdr input batcher currently recognizes only SGR buttons 64 and 65 (vertical
wheel). It will also recognize buttons 66 and 67 (horizontal wheel) while
preserving modifier bits and the existing first-event-immediate, rest-of-frame
batching behavior.

No new scroll transport is introduced. Normal scrollback, touch vertical
scroll fallback, and non-Herdr terminal behavior remain unchanged.

## Error handling and compatibility

- A malformed metadata event is ignored without replacing valid cached state.
- An event for an unknown workspace or pane is not invented locally; normal
  lifecycle refresh discovers newly created resources.
- Existing protocol compatibility remains `14..=16`.
- Removed upstream `custom_status` fields will no longer be read as the
  preferred status detail; `message`, semantic state, and display labels
  remain supported.
- The JSON request size cap remains 1 MiB, which is sufficient for Herdr's
  512 KiB base64 graphics-set limit plus envelope overhead.
- Popup panes are not represented as normal pane ids and do not enter the
  tiled session snapshot. WebShell will allow the JSON `popup.close` method
  but will not claim popup rendering support.

## Module boundaries

- `src/herdr_socket_contract.json` owns the versioned method and subscription
  contract.
- `src/herdr.rs` parses the upstream snapshot and exposes typed pane/workspace
  presentation metadata.
- `src/frontend/src/herdr-socket-api.ts` owns event subscription definitions
  and raw event resource parsing.
- A focused Herdr state-event module under `src/frontend/src/` owns immutable
  state patching and refresh policy.
- `src/frontend/src/herdr-views.ts` owns Herdr tab label and tooltip
  presentation.
- `src/frontend/src/herdr-wheel-input-batcher.ts` owns SGR wheel recognition
  and frame batching.
- `src/frontend/src/main.ts` remains the composition layer and receives only
  event wiring changes.

## Verification

Focused tests will cover:

- exact 0.7.4 contract version, revision, method count, and subscription count;
- inclusion of the new JSON methods and subscriptions and continued exclusion
  of `pane.graphics.stream`;
- no accidental `pane.scroll_changed` subscription;
- parsing workspace tokens and pane terminal-title metadata;
- immediate immutable state replacement for both new event types;
- no state corruption from malformed or unknown resource events;
- generic versus explicit Herdr tab label selection;
- horizontal SGR buttons 66/67, modifier handling, and frame batching; and
- Rust snapshot parsing for pane metadata and old-protocol fallback behavior.

Release verification will run frontend tests, TypeScript type checking, the
frontend production build, Rust tests, formatting checks, and diff whitespace
checks before versioning, tagging, and pushing.

## Non-goals

- Do not add a pane attach sidecar or resize the real Herdr PTY through a new
  observer.
- Do not subscribe to `pane.scroll_changed`.
- Do not proxy ZMODEM, Kitty graphics streams, or any other raw binary protocol
  through the JSON SockAPI bridge.
- Do not render Herdr popup panes inside the browser tiled layout.
- Do not add WebShell controls for Herdr-native `copy_on_select`, sidebar
  `rows`, `row_gap`, or copy-mode search settings.
- Do not place parsing, label selection, backend compatibility, or wheel
  recognition helpers in `main.ts`.

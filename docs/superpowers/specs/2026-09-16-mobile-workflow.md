# Mobile terminal workflow improvements

User approved the QuickTUI assessment and implementation, then clarified that convenience and preserving familiar workflows take precedence over redesign. Toolbar controls remain icons. New functionality is built in and frontend-only, independent of plugins.

1. Add an optional multi-line draft composer. Drafts live only in memory per selector/session/pane (including the actual Herdr pane); newline edits the draft. Explicit Insert and Send+Enter actions; no automatic execution on paste or row selection. Preserve draft on failure/close and prevent sends to a switched/closed/replaced target. Editing never persists secret text in localStorage or history. Limit text to 64 KiB UTF-8.
2. Reuse the existing navigation page icon as a compact directional panel toggle. User explicitly rejects duplicate keys: remove default main-row arrow keys, keep exactly one arrow set in navigation; do not add copies of main Tab/Enter/Ctrl/Esc to navigation. Preserve user-customized layouts. While the panel is open hide the underlying key rail so two direction pads are never visible together. Preserve keyboard open/closed state, sticky modifiers, cancellation and long-press repeat. The panel must not be a modal that steals IME focus.
3. Evolve the existing quick-phrase entry into a searchable command/phrase panel with Recent / All / Keys. Reuse user phrases and sendEnter metadata; display full text, group and explicit Enter indicator. Keep search input unfocused until tapped on mobile. No fabricated installed-agent command presets. Selecting phrases uses their explicit existing sendEnter behavior. Only successful uses update recent metadata. Revalidate exact target when dispatching; no stale modal actions.
4. Refine existing overview with a check mark for current pane, clear names and secondary backend/connection state and pane counts. Keep existing tab/pane activation, ordering and backend grouping. Preserve focus/scroll on refresh; do not add an alternate navigation system.

Existing CSS theme/font/motion tokens; opaque surfaces; 44–48 CSS px actions, 320px width, safe areas and visualViewport height. Reduced motion, keyboard/AT activation, dismiss and focus restoration. Mobile-only modules and CSS under src/frontend/src/mobile/. main.ts contains only composition and event call-throughs. No new runtime dependencies or backend/agent changes.

Checks: focused node tests, complete npm test and npm run build, real browser pointer and keyboard interactions with production controllers at 320/390px and keyboard-sized viewports; target changes, Chinese/multiline input, repeat cancellation, double tap, custom layout, disabled/disconnected targets, palette filtering and sendEnter. Release after passing as next patch, with full release build and LPK validation; publish branch/tag as requested.

Modal toolbar actions open synchronously on the native click, after the pointer gesture has been validated; they must not open on pointerup and expose submit buttons to the pending compatibility click. The system-keyboard toggle and ordinary keys remain pointerup actions. Native text insertion honors observed bracketed-paste mode; Herdr uses the already allowlisted pane.send_input with separately encoded Enter keys.

Follow-up: Navigation is now a regular category in the existing lower key rail, with arrows ordered first. It does not float, toggle closed, dismiss on outside clicks or consume Escape; category selection remains until another category is selected. No duplicate default arrows or custom-layout rewrites.

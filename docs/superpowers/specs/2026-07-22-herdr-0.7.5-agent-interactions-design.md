# Spec: Herdr 0.7.5 SockAPI and Agent Interactions

## Objective

Update the sibling Herdr source checkout to the current `origin/master` containing
v0.7.5, adapt WebShell to SockAPI protocol 17, and expose the new Agent workflow
without replacing existing terminal or AI Chat behavior.

Users must be able to:

- use Herdr 0.7.5 without a protocol-newer warning;
- call the current JSON SockAPI method set while obsolete `agent.send` is rejected;
- see Agent detection and release events described accurately;
- right-click a Herdr terminal on desktop and receive the WebShell pane menu rather
  than sending the right click to Herdr's native TUI menu;
- inspect and locally filter Herdr Agents by status from the existing Herdr workspace
  menu, then focus the selected Agent pane; and
- submit the AI Chat composer text to the active Herdr Agent with one atomic
  `agent.prompt` request that waits for `done` or `blocked`.

The existing OpenAI-backed AI Chat send action remains independent. Herdr Agent
prompting is an additional action and does not require an OpenAI API key.

## Project Structure

```text
src/herdr.rs
  Authorized LightOS-to-Herdr bridge, versioned protocol compatibility,
  snapshot parsing, and method-aware request timeout policy.

src/herdr_socket_contract.json
  Embedded version, revision, protocol, JSON methods, and subscriptions.

src/frontend/src/herdr-*.ts
  Cross-platform Herdr state, views, event presentation, Agent filtering,
  and SockAPI parsing. No new pure Herdr helpers belong in main.ts.

src/frontend/src/plugins/ai-chat/
  AI Chat-specific Herdr Agent target and prompt behavior.

src/frontend/src/restty-context-menu.ts
  Cross-platform Restty menu opening plus Herdr desktop pointer interception.
```

## Code Style

Use narrow typed helpers and return `undefined` for invalid external JSON rather
than partially trusting it:

```ts
export function herdrAgentInfo(value: JsonRecord | undefined): HerdrAgentInfo | undefined {
  const paneId = stringField(value, "pane_id");
  const status = stringField(value, "agent_status");
  if (!paneId || !status) return undefined;
  return { pane_id: paneId, agent_status: status };
}
```

`main.ts` may bind events and coordinate calls, but parsing, filtering, request
construction, and rendering helpers must live in their owning modules.

## Testing Strategy

- Contract tests independently assert the released schema metadata and method delta.
- Parser tests use literal Herdr response fixtures for Agent snapshots and prompt results.
- View tests assert filtered Agent rows and disabled/available AI Chat actions from
  exported rendering functions.
- Controller tests exercise the public AI Chat controller method with fake dependencies
  and verify the `agent.prompt` call, message history, busy state, and final status.
- Context-menu regression tests exercise capture interception and event forwarding for
  Herdr desktop, coarse touch, and unaffected non-Herdr desktop paths.
- Rust timeout tests verify long-wait methods receive a bounded method-aware timeout while
  ordinary requests retain the six-second default.

## Boundaries

- Always: authorize the LightOS selector before every Herdr request; allowlist method
  names; cap wait time; preserve protocol 14-16 fallback; localize user-visible copy;
  keep new modules focused.
- Ask first: adding dependencies, changing persistence, changing Herdr target state with
  `agent.view.set/clear`, publishing a WebShell release, or changing the lightweight
  target agent protocol/version.
- Never: expose arbitrary shell execution through SockAPI params; allow
  `pane.graphics.stream` through the JSON bridge; send desktop Herdr right clicks into
  the PTY while opening the WebShell menu; require OpenAI credentials for Herdr Agent
  prompting; add feature logic to `src/frontend/src/main.ts` beyond wiring.

# Herdr 0.7.5 SockAPI Adaptation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Update the sibling Herdr checkout and make WebShell compatible with the Herdr 0.7.5 JSON SockAPI and protocol 17.

**Architecture:** Keep the existing LightOS-to-Herdr socket bridge and persistent-session model. Sync the embedded method/subscription allowlist from Herdr's released JSON schema, retain protocol 14-16 compatibility, and move Herdr event copy out of `main.ts` into a focused presentation module that understands the new agent-release event fields.

**Tech Stack:** Rust 2024, Axum, Serde JSON, TypeScript 5.9, Node test runner, Cargo tests.

## Global Constraints

- Use the clean sibling checkout at `/home/czyt/code/rust/herdr`, fast-forwarded to `origin/master` revision `0f161fac287011b3e216383e2b8482f049fd6a7b`, which contains tag `v0.7.5`.
- Embed Herdr source version `0.7.5`, protocol `17`, schema version `1`, 89 JSON methods, and 26 subscriptions.
- Remove the obsolete `agent.send` method and allow `agent.send_keys`, `agent.prompt`, `agent.wait`, `agent.view.set`, and `agent.view.clear`.
- Continue excluding `pane.graphics.stream`, because it uses a separate binary Unix-socket protocol rather than the newline-delimited JSON bridge.
- Keep `MIN_SUPPORTED_HERDR_PROTOCOL_VERSION` at `14` so Herdr 0.7.2-0.7.4 integrations remain usable.
- Keep `src/frontend/src/main.ts` limited to orchestration; event presentation logic belongs in a focused Herdr module.
- Do not bump the WebShell lightweight `AGENT_VERSION` or `MIN_SUPPORTED_AGENT_VERSION`; this is provider/frontend compatibility work only.
- Do not bump or publish the application version unless separately requested.

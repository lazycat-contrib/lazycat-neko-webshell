# neoko-terminal 0.2.0 / 桌面 0.3.0 验收记录

本次验收对应 WebShell 0.13.3、共享客户端 0.2.0、桌面包 0.3.0，固定 NSH 0.5.0
提交 `f4d68f7f9f31eb7b3ecc8a4cbc31096d5c6238a1`。记录的是已完成的测试，不代表所有平台的真机验收。

## 公开 Relay 业务链路

测试连接 `https://neko-relay.czyt.eu.org`，经过真实 WSS、Noise 加密、设备配对和主机批准。

- 使用实际 Herdr 0.9.5 及本地 agent stdio / Unix socket 桥接，执行命令并验证输出标记；验证普通 / application cursor、Home / End 等 VT 按键和 bracketed paste 的实际字节。
- 使用真实 ManagedTerminal PTY，验证原生输入被 Web 订阅方读取、Web 输入被原生订阅方读取、控制权取得和收回、只读写入拒绝、detach 保留 PTY。
- 使用生产 Python 文件辅助程序完成分块上传、原子提交、列目录、下载和 SHA-256 校验；验证只读限制和路径穿越拒绝。

LightOS 用户归属及目标分派使用测试状态内的受限替身；这不是已部署 LightOS 浏览器委托票据的全栈验收。
Relay 协议没有发生变化，不需要重新部署公开 Worker。

## Android 原生应用

在 API 35 模拟器安装实际 NSH APK，通过原生 UI 设置公开 Relay、输入新设备码、批准配对、
重新启动后自动连接、选择普通终端、明确取得控制权，并通过原生中文输入框发送 shell 命令。
UI 自动化确认返回文本；主机测试独立确认真实 PTY 输出完整标记行，排除仅检测命令回显。

此测试使用隔离测试签名，不能作为发行安装包。正式 APK 必须使用既有生产证书，并独立核对
产物摘要、签名、版本、ABI 和 16 KiB 对齐。中文输入使用 Android 原生字段的自动化赋值，
不代表已覆盖各第三方输入法的完整预编辑行为。

## 桌面界面与发布边界

Linux 原生窗口完成浅色、深色、窄屏及抽屉截图检查，验证终端输入、中文输入框和显示状态。
Windows 和 macOS 的构建及包内容检查应以本次发布 CI 结果为准；没有这些平台的真机操作记录。
桌面平台保留系统凭据身份，Deb 包替换旧包，可执行文件和显示名统一为 `neoko-terminal`。

当前原生应用是连接 WebShell 主机的客户端。原生桌面之间配对所需的桌面主机模式将在本次发布后继续开发；本版本不宣称已经支持。
